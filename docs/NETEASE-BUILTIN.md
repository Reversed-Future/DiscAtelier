# 内置网易云模块

2026-10-21。本轮为本地功能预览，没有发布新版本或生成安装包。程序未启动，实际窗口操作由用户验收。

## 使用与手动测试

预览程序：`E:\ToolsForMyself\DiscAtelier\target\release\DiscAtelier-netease-preview.exe`。直接在该位置启动，旁边的 `netease-runtime` 文件夹必须保留；单独复制 EXE 会缺少内置运行组件。安装版的资源配置也已接入，未来打包时会一同安装。

1. 退出旧版，再打开预览。设置 → 网易云，选择“内置”并保存；未配置过的用户默认就是内置。此前保存过自定义 URL 的用户会保留原设置，需要手动切换一次。
2. 打开音乐收藏详情 → 网易云资料，搜索专辑并打开结果。第一次查询会启动后台模块，按钮显示“读取中”；不需要运行终端、部署服务、填写端口或安装 Node.js。
3. 连续查询另一张专辑，确认可以继续搜索、分盘查看并保存。仍使用原来的补充资料表，不覆盖 Discogs 资料、封面和购入记录。
4. 退出软件，后台模块应随之结束。再次打开软件但不进行在线网易云查询，应没有本软件启动的 Node 进程；查看已保存补充资料也不会启动它。
5. 如果想检查进程，请在任务管理器的“详细信息”中显示命令行，识别本程序旁 `netease-runtime\node.exe` 与 `runner.cjs`；不要把其他软件使用的 Node 进程算入测试。
6. 查询期间退出，软件应中断等待并清理后台进程。网络不可用时显示错误，之后恢复网络可重试；查询失败不会覆盖已保存资料。

高级场景：设置 → 网易云选择“自定义”，才会出现服务地址。自定义模式继续使用原 HTTP 适配器，不会启动内置进程。已经启动的内置进程在本次软件退出时回收。助手的网易云查询遵循同一模式，普通收藏查询不会启动 Node。

首次运行上一轮功能预览会由 schema 6 升到 7，并在迁移前自动备份；本轮没有新增数据库迁移。已升级 schema 7 的库不能直接给旧的公开 0.1.6 打开。

## 实现

- `crates/netease-runtime`：单一进程管理器，创建时不访问网络、不启动进程。首个有效查询启动；并发请求串行复用；超时、无效响应或异常退出后清理，下次查询重新创建。
- `packages/netease-sidecar/runner.cjs`：通过私有 stdin/stdout JSON 行通信，仅注册专辑搜索和专辑读取。调用锁定版本的社区 API 模块，不启动 HTTP 服务器，不绑定端口。
- 返回内容只有上游响应的 `body`，不传回 Cookie、请求配置或上游错误堆栈。日志不写入用户目录，临时匿名凭据写入应用数据目录的 `netease-cache`，与系统临时目录分离。
- 后台进程使用 `CREATE_NO_WINDOW`；Windows Job Object 开启 `KILL_ON_JOB_CLOSE`。正常退出、查询期间退出及父进程异常结束都会结束本应用拥有的子进程，不扫描或终止其他 Node 服务。
- 单次等待上限 35 秒、响应上限 2 MiB；退出标记每 50 ms 检查一次，中断后回收进程。未实现空闲自动退出，首次使用后保持到软件退出以复用加载结果。
- 模式保存到原 `integration-settings.json` 的新增内部字段 `neteaseMode`。旧文件缺少该字段时，已有 URL 保持自定义；空 URL 使用内置。原 URL 留存，来回切换不必重复填写。
- 配置界面沿用 MiSans、自定义选择框、固定窗口与短淡入，只在自定义模式展示 URL 输入。

内置资源 4,828 个文件，共 **137,536,527 字节（约 131.2 MiB）**，其中 Node 可执行文件 86,973,768 字节。这是未压缩资源大小，不是安装包体积，也不是运行内存。
