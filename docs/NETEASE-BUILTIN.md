## 使用与手动测试

最新搜索预览程序：`E:\ToolsForMyself\DiscAtelier\target\release\DiscAtelier-netease-search.exe`。包含前一轮启动路径修复。直接在该位置启动，旁边的 `netease-runtime` 文件夹必须保留；单独复制 EXE 会缺少内置运行组件。安装版的资源配置也已接入，未来打包时会一同安装。

1. 退出旧版，再打开预览。设置 → 网易云，选择“内置”并保存；未配置过的用户默认就是内置。此前保存过自定义 URL 的用户会保留原设置，需要手动切换一次。
2. 打开音乐收藏详情 → 网易云资料，搜索专辑并打开结果。第一次查询会启动后台模块，按钮显示“读取中”；不需要运行终端、部署服务、填写端口或安装 Node.js。
3. 连续查询另一张专辑，确认可以继续搜索、分盘查看并保存。仍使用原来的补充资料表，不覆盖 Discogs 资料、封面和购入记录。
4. 退出软件，后台模块应随之结束。再次打开软件但不进行在线网易云查询，应没有本软件启动的 Node 进程；查看已保存补充资料也不会启动它。
5. 如果想检查进程，请在任务管理器的“详细信息”中显示命令行，识别本程序旁 `netease-runtime\node.exe` 与 `runner.cjs`；不要把其他软件使用的 Node 进程算入测试。
6. 查询期间退出，软件应中断等待并清理后台进程。网络不可用时显示错误，之后恢复网络可重试；查询失败不会覆盖已保存资料。

高级场景：设置 → 网易云选择“自定义”，才会出现服务地址。自定义模式继续使用原 HTTP 适配器，不会启动内置进程。已经启动的内置进程在本次软件退出时回收。助手的网易云查询遵循同一模式，普通收藏查询不会启动 Node。

首次运行上一轮功能预览会由 schema 6 升到 7，并在迁移前自动备份；本轮没有新增数据库迁移。已升级 schema 7 的库不能直接给旧的公开 0.1.6 打开。

## 实现

### 2026-10-21 搜索分页与封面

搜索类型保持社区接口 `/search` 的 `type=10`（专辑）；选中专辑后通过 `/album` 读取曲目。之前固定 `limit=20, offset=0` 且丢弃总数，现在两种服务模式都传递页偏移并保留 `result.albumCount`，底部可翻页。每次仍只请求一页，避免一次加载所有结果；翻页使用已提交关键词，不混用输入框里尚未提交的修改。请求失败保留原页，返回搜索保留结果与页码。

封面映射已捕获响应中的 `result.albums[].picUrl`，仅接收网易云图片域名，将 HTTP 图片地址改为 HTTPS。CSP 的图片规则增加该 CDN；封面懒加载、异步解码和淡入，失败显示固定占位。结果页及由结果进入的详情展示封面；本次不把远程图片写进补充资料表，也不替换收藏的 Discogs 封面或模型。已有保存资料重新打开时仍沿用现有文本与曲目展示。

验收：退出旧程序，打开最新搜索预览；搜索 `Lemon`，观察封面、总数及分页，进入第二页后打开专辑，再返回搜索，确认仍在第二页；修改输入但不提交后翻页，确认仍使用原搜索关键词；重新搜索后回到第一页。检查无图占位、固定窗口与独立列表滚动。上游没有收录或没有返回的专辑不会因分页自动补齐。

验证使用现有捕获文件核对 `albumCount=513`、`picUrl` 字段及 HTTPS 转换（历史样本，不是当前实时结果）。11 项相关 Rust 单元测试、1 项捕获响应校验、24 项前端／脚本测试通过；脚本测试覆盖真实 runner 的分页参数转发及无效偏移拒绝，无网络或桌面操作。最终界面及联网验收由用户执行。

严格 Clippy、TypeScript／Vite、Tauri Release 构建及发布预检通过。首次构建遇到文件占用，请用户退出后原命令重试成功；未代替用户结束进程。打包 runner 与源码 SHA-256 一致。搜索预览 EXE SHA-256：`2d3544c1f7beeb37cee67debe2bb83df37db8f17bad1f902a9d48f8436c8153d`。本次没有生成安装包或上传 GitHub。

### 2026-10-21 启动路径修复

用户报告“内置网易云已退出”。复现确认：Tauri 的 Windows 资源目录来自规范化后的可执行文件路径，包含 `\\?\` 前缀；直接作为 Node 主脚本参数时，Node 22.23.3 在入口加载阶段报 `EISDIR: illegal operation on a directory, lstat 'E:'`，退出码 1。先前真实 API 测试用了普通路径，未覆盖桌面运行时提供的路径形式。

启动适配器现在使用 `dunce::canonicalize` 解析 Node、脚本和缓存路径，仅在能保持相同目标的情况下转换为兼容格式，不手动截断或猜测路径。新增包含中文、空格以及 Windows 规范路径的回归测试，先复现相同错误，再验证修复。既有公开 API 检查也改用规范资源路径，防止后续再次漏测。

本次验证：7 项生命周期与路径测试通过；打包目录真实 runner 的独立离线启动／管道响应检查通过；严格 Clippy 通过。离线检查不发送上游查询，不代表本轮已完成真实联网查询验收；搜索与专辑读取仍由用户在修复版中手动确认。没有操作窗口、读取光盘或改动用户收藏。

修复版 TypeScript／Vite 与 Tauri Release 构建通过，发布预检无问题。`DiscAtelier-netease-fix.exe` SHA-256：`f12208f795498e438a09b8950505c957e4582266e39e4bd1819f5241c3a4298c`。旧预览保留以供区分，本次请使用带 `fix` 的程序。

- `crates/netease-runtime`：单一进程管理器，创建时不访问网络、不启动进程。首个有效查询启动；并发请求串行复用；超时、无效响应或异常退出后清理，下次查询重新创建。
- `packages/netease-sidecar/runner.cjs`：通过私有 stdin/stdout JSON 行通信，仅注册专辑搜索和专辑读取。调用锁定版本的社区 API 模块，不启动 HTTP 服务器，不绑定端口。
- 返回内容只有上游响应的 `body`，不传回 Cookie、请求配置或上游错误堆栈。日志不写入用户目录，临时匿名凭据写入应用数据目录的 `netease-cache`，与系统临时目录分离。
- 后台进程使用 `CREATE_NO_WINDOW`；Windows Job Object 开启 `KILL_ON_JOB_CLOSE`。正常退出、查询期间退出及父进程异常结束都会结束本应用拥有的子进程，不扫描或终止其他 Node 服务。
- 单次等待上限 35 秒、响应上限 2 MiB；退出标记每 50 ms 检查一次，中断后回收进程。未实现空闲自动退出，首次使用后保持到软件退出以复用加载结果。
- 模式保存到原 `integration-settings.json` 的新增内部字段 `neteaseMode`。旧文件缺少该字段时，已有 URL 保持自定义；空 URL 使用内置。原 URL 留存，来回切换不必重复填写。
- 配置界面沿用 MiSans、自定义选择框、固定窗口与短淡入，只在自定义模式展示 URL 输入。
