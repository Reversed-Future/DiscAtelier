## 新增能力

原有 7 个工具保留，新增 6 个，总计 13 个：

| 工具 | 范围 |
| --- | --- |
| `propose_add_collection` | 从 Discogs 发行、网易云专辑或用户提供的名称／创作者建立收藏提案。Discogs 使用发行载体；网易云和手动录入必须明确载体。收藏状态必须明确，购入详情留空并展示。 |
| `propose_netease_supplement` | 替换指定音乐收藏版本的网易云简介、数字发行资料和数字曲目。保留实体资料、Discogs 曲目、封面。同一专辑保留仍有效的手动关联，换专辑会展示移除的关联。 |
| `propose_cover` | 使用已关联的网易云专辑封面或收藏原来源的 Discogs 封面；展示新旧图片。 |
| `get_playback` | 读取当前内置播放器状态。 |
| `play_music` | 播放已关联专辑中的真实歌曲；沿用账号音源权限和现有内置播放器。 |
| `control_playback` | 暂停、继续、停止、按秒跳转；网易云关联专辑内上一首／下一首。 |

收藏变更必须点击确认卡片中的按钮。聊天里说“确认”不能提交，模型也没有提交工具。确认卡显示实际准备保存的资料，包含版本级影响范围、简介和曲目变化，以及封面前后对照。新增前展示检索到的已有收藏，使用相同的事务和请求回执防止重复确认造成重复入库。

提案的实际数据保存在后端内存中，界面只能提交提案编号，不能提交替代的保存内容；会话保存可读的预览文本。提案 30 分钟后失效，应用重启后需取消旧提案再重新提出。资料或封面准备后若收藏版本已改变，保存会拒绝旧版本，要求重新准备。新操作确认后清除旧状态撤销，避免误撤销不相关操作；现有状态修改仍支持原来的单次撤销。新增、资料和封面没有新增自动撤销工具。

助手播放会进入现有右下角队列及最多三个专辑历史；不额外开启播放器窗口。它可以控制已开始的光盘播放，但没有扫描、启动、弹出或写入光盘工具，上下曲限定网易云关联专辑。播放工具的提示词要求用户明确播放指令，闲聊和推荐不自动播放。

## 流式与故障行为

- 兼容 Chat Completions 请求使用 `stream: true`，SSE 文本分段传到 Tauri Channel；界面展示逐步到达的文字。
- 按工具索引累积函数名和 JSON 参数，必须收到完整结束标记和有效完成原因才执行；不执行断流或截断的工具参数。
- 支持 UTF-8 跨网络包、CRLF、注释行、使用量空 choices 及兼容服务返回普通 JSON。普通 JSON 服务可以正常回答，但只能一次显示回复。
- 兼容 `delta.tool_calls: null`（小米 MiMo 等 OpenAI 兼容服务会在无工具的文本和推理分片中显式返回）与 `reasoning_content`；空值按空数组处理，不中断流式回答。
- 网络等待支持取消：停止会丢弃进行中的 HTTP 请求，保留已显示的部分文字；已经执行完的工具操作不会因此回滚。正在执行的独立资料查询需要等待其自身返回后停止。
- 限制单次传输 2 MiB、事件／行 64 KiB、回答 32 KiB、工具参数 4 KiB；维持每轮最多 8 次工具调用和原有上下文上限。
- 关闭浮窗不会取消对话。消息滚动到上方时，文字增量不强制拉回底部。
- 助手回复以安全的轻量 Markdown 渲染（标题、列表、引用、代码块、强调和 http/https 链接），原始 HTML 只按文本显示。
- 发送后输入框立即清空并显示带动效的用户消息；发送／停止按钮位于输入框内右下角。最后一条用户消息可在空闲状态重试，重试会丢弃中断的回答和工具消息后重新请求，不重复用户消息。

字段依据 [OpenAI Chat Completions 官方协议](https://platform.openai.com/docs/api-reference/chat/object?lang=ruby)，测试使用本地隔离 HTTP 服务，没有请求真实 AI 接口。

## 提示词与性格

实际完整提示词位于 `crates/agent-harness/src/prompt.txt`，通过 `include_str!` 编译使用。新定位是陪用户听音乐、聊收藏的 AI 伙伴：自然温和、有好奇心和自己的判断；允许聊音乐感受、收藏故事、日常与心情，不把每句话都转成任务或追问。区分主观解读与工具证据，不编造真实生活经历、情感或永久记忆，也不制造排他依赖。

对收藏、价格、外部版本和音源权限继续要求实际证据；写入必须预览并点击确认。密钥仍由原有凭据管理器处理，不进入模型工具资料。

## 验证

已通过 `npm run build`、53 项现有 JavaScript 测试、全工作区 Rust 测试和严格 Clippy。新增 11 项测试覆盖：流式参数拼接、截断／并行工具拒绝、分段文字、断流、取消网络等待、UTF-8 分包、响应限额、新增确认／取消／防重复、重启或过期提案、资料版本冲突和封面保存范围。最后的内存结构及命令参数调整另跑助手与传输专项测试。

使用临时隔离数据库和本地 HTTP 样本，未操作用户窗口、个人收藏或光盘。真实模型语气、工具选择、实际播放出声和视觉交互由用户手动验收；自动测试不代表这些已经实测。

## 手动测试

先退出旧预览，再打开本轮预览；在设置中使用支持 Chat Completions 和函数工具调用的兼容接口。

1. 闲聊：“今天有点累，想聊聊最近听的歌。”查看回复是否自然逐段出现；点击停止，确认不再继续生成。
2. 搜索并添加：“查找这张专辑的 Discogs 发行，我想加入想购入。”核对发行后提出新增；先取消，确认未入库，再重新提出并按需确认。
3. 手动入库可明确说：“添加一套测试收藏，音乐分类，CD，名称……，创作者……，状态想购入。”只有点击确认才新增。
4. 对已有音乐收藏要求补充网易云资料：核对简介、新旧曲目和手动关联变化；确认后查看详情。
5. 要求“把这张收藏封面换成已关联的网易云封面”：核对左右图片，分别测试取消与确认。
6. 要求播放某已关联歌曲，再说暂停、继续、下一首、跳到 30 秒、停止；确认右下角队列与实际声音同步。
7. 提案出现后，先手动编辑该版本，再确认旧提案：应提示资料改变，不覆盖新编辑。重启后旧提案应要求重新准备。
