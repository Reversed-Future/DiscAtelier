# 实体 Disc 与资料小标题

本次修正用于已经保存的曲目和新导入资料，不要求重新获取 Discogs 资料。

## 规则

- 版本 `media` 的每个元素代表一份实体载体；导入时沿用 Discogs `formats[].qty` 展开结果。CD + 2 BD 在编辑器中固定显示三个同级区域，包括尚无曲目的 Disc。
- 用户明确指定的所属 Disc 优先。其后结合原始 `heading` / `index` 结构、实体数量及已有曲号证据判断。只有完整分组与光盘数量相符且不存在已知冲突时，才能按来源顺序对应实体；不会按曲目数量平均切割。
- 曲号只作辅助。现有实样中的 `CD12` / `BR1`、`CD-1` / `DVD-1`、`BD1-1` / `BD2-1`、`1-1` / `2-1` 保持支持；未知格式仍能依靠来源结构分盘，无法判断时显示未分盘。黑胶面号不按光盘推断。
- 分盘标题单独显示及编辑，不混入歌曲行。盘内小标题有明确类型标识，支持新增或改为曲目。曲目组保留原有嵌套结构。
- 编辑器的所属 Disc 选项来自实体载体。自动项显示实际解析盘号，允许手动纠错；仍须点击保存资料才写入。

## 数据与兼容

新增内部可选字段 `ReleaseTrack.disc_number`（从 1 开始的实体序号）和 `ReleaseTrack.heading_kind`（`disc` / `section`）。这是应用自身定义，不冒充 Discogs 字段。它们随现有 `edition_content.content_json` 存储和备份，无须修改数据库 schema。

读取旧资料仅生成显示分组，不改写保存的原始曲号、标题、嵌套、Credits 或购入资料。分盘修正不会通过重写曲号完成。前端展示、网易云匹配、播放队列、光盘关联共用对应的结构规则；前后端使用同一组回归样例。

原整表 `unassigned` 的网易云关联在拆分显示时保留；同一实体的旧分组标识与手动 Disc 标识对应到相同载体。只在用户明确编辑关联时持久化当前分组，清除旧别名，避免取消关联后又被旧记录恢复。彼此冲突的关联不凭空选择。

## 验证

覆盖旧 Pop Virus 资料、未知曲号、CD + 2 BD、嵌套曲目组、Bonus 小标题、手动分盘、原顺序、旧关联、保存校验及备份恢复。界面检查使用合成资料和模拟 IPC，不访问实际收藏库。

构建与验证结果记录于 ROADMAP.md；本功能纳入 0.1.28 正式发行。

## 同名歌曲的匹配范围

自动匹配按每张 Disc 分开运行。其他 Disc 中的同名现场曲目不会使当前 CD 被认定为重名；当前 Disc 内的重复标题和多个网易云专辑之间的歧义仍需额外证据或明确关联。大小写、标点和繁简转换只用于显示标题的比较，不改变原始标题或歌曲关联键。

未指定分盘音源时，已识别的 DVD／BD 不参与录音室专辑自动匹配；选择该盘的音源专辑后，允许在明确范围内匹配。载体元数据优先于原曲号，手动单曲关联始终优先。`tests/disc-song-match.test.mjs` 使用截图标题与合成重名曲目验证 CD、BD、DVD、未知曲号、手动指定和队列行为，不包含用户收藏库或购入数据。
