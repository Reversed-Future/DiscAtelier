# 购物截图填写（未发行预览）

入口：详情 → 购入 → 编辑购入；添加收藏流程的购入步骤也使用相同控件。

支持文件选择（单张／多张 PNG、JPEG、WebP）和表单内 Ctrl+V 图片粘贴，每轮 1–6 张。选择图片不会自动发送，点击“识别”后才使用设置中的 AI 接口和模型。模型需要支持图片输入，不新增独立密钥或重复设置。

AI 返回商品／订单记录、截图编号、字段与原文依据。用户选择记录并勾选字段后点击“填入所选字段”，只改变编辑草稿；普通“保存购入”／“加入收藏”仍是唯一保存入口。关闭编辑不会保存。金额与币种作为一个字段应用，未识别／未选择的字段保留原值；存放位置和备注完全不由识别器填写。

可提取：明确的购入价格和币种（CNY、HKD、JPY）、付款日期、平台／店铺、完整可见购买链接、明确已收货或在途状态。系统提示要求多商品／多数量无法分摊时不使用整单总额，不猜日期年份、币种或拼接链接。同一订单的多张截图可合并，不同订单分开列出。AI 仍可能误读，界面始终展示依据和修改前后值，需用户核对。

## 实现与数据边界

- `forms/purchase/` 分离图片准备、识别交互、核对和草稿合并；Rust `purchase_recognition/` 分离图像校验、请求组装、返回字段校验。没有写收藏库或助手工具的权限入口，无数据库迁移。
- 复用已有 AI 配置及系统凭据管理器。请求沿用 HTTPS／本机 HTTP 限制，不跟随重定向，120 秒总超时，2 MiB 响应限制。
- 按 [Chat Completions 官方图像内容结构](https://platform.openai.com/docs/api-reference/chat/object) 发送 `messages[].content` 中的 `text` 和 `image_url`，后者为内存 data URL；非流式 JSON 响应使用 `choices[0].message.content`，只接受正常结束结果。
- 本应用新定义的返回协议是 `{records:[{title,sourceImages,fields:[{key,value,currency,evidence}],warning}],message}`。这不是商城接口字段映射。允许的 key 仅 `price`、`acquiredAt`、`seller`、`purchaseUrl`、`status`；未知／重复字段、无依据、无效日期／货币／链接及不完整 JSON 均拒绝。
- 原图每张至多 12 MiB、3200 万像素；浏览器重编码为 JPEG，最长边 4096 像素，去除文件元数据。Rust 再核对格式、解码、尺寸和大小；总传输 data URL 至多 24 MiB。长截图文字不清时，请裁成多张再识别。
- 截图及识别结果只驻留当前表单／请求内存，不保存到收藏、助手会话、日志或本地备份。发往用户设置的 AI 服务后，该服务的数据处理由其自身政策决定。提示词排除收件人、电话、地址、支付账号等内容，但发送的是用户所选截图本身，可先自行遮挡。
