# 助手提示词与手动验收

2026-10-22 开发预览。运行提示词位于 `crates/agent-harness/src/prompt.txt`，工具定义位于同目录 `tools.rs`。提示词编译进入程序，每次模型请求重新附加；没有数据库迁移，也不修改已有收藏或会话记录。

## 本轮调整

- 将用户提供的完整行为规范精简为交流、证据、确认、多专辑、播放和语气示例六部分。普通背景知识可以自然交流；收藏、版本、价格、权限等具体信息仍需依据。
- 明确提案与保存的区别：模型提出变更，用户点击界面确认，应用后端保存。没有向模型开放确认或通用写入工具。
- `get_copy` 的 `neteaseAlbums` 与 `discAlbumLinks` 表示全部数字专辑和已有分盘绑定，`netease` 仅为兼容单专辑信息。补全按专辑 ID 追加或更新，保留其他专辑与绑定。
- 同步更正工具说明中旧的“替换资料”及单专辑播放措辞，参数和执行实现不变。
- 助手目前不能修改 Disc 绑定、数字专辑顺序或独立单曲关联；封面提案只能选择来源，不能指定多张网易云专辑中的某一张。独立单曲可由播放后端处理，但当前收藏查询工具不返回它的关联明细，助手不能凭空确认歌曲 ID。
- 上下曲沿用应用已生成的有效列表，不能靠提示词自行构建、排序或覆盖队列。没有有效列表时，需先在收藏曲目中选择歌曲。

## 手动测试

完全退出当前 DiscAtelier，自行打开本轮测试程序，在右下角助手点击“新会话”。使用已配置的兼容接口；不需要提供密钥给开发者。

1. **自然聊天**：发送“今天不想折腾收藏了，只想随便聊聊音乐。”应自然接话，不自动查询、入库或播放；接着说“先不聊了”，应自然收尾。
2. **收藏事实**：发送“查一下我收藏的《24时》，有哪些网易云专辑，两个 Disc 分别绑定哪张？”应先查询收藏，再按实际返回的关联说明；不按 PM／AM 名称猜分盘，也不把兼容单专辑字段当成全部。
3. **能力边界**：发送“把 Disc 1 绑定 PM，Disc 2 绑定 AM。”当前应说明需要在收藏界面设置，不能声称已修改，也不能提交补全资料来冒充分盘绑定。
4. **确认流程**：选择一份愿意用于测试的收藏，请助手把状态改为一个不同的状态。应出现具体变更卡；未点“确认修改”前收藏状态不变。点击“取消”应保持原值。只有确实希望变更时才点确认，并核对结果。“确认保存”用于新增、补全和封面提案。
5. **多专辑补全**：请求更新其中一张已关联专辑的资料，检查预览应针对该专辑并说明版本级影响；可取消。若选择保存，核对另一张专辑、两个 Disc 绑定和独立单曲关联仍在。
6. **播放意图**：先在收藏曲目中自行播放一首已关联歌曲，让应用建立列表；对助手说“这首怎么样”不应切歌，再说“暂停”“继续”“下一首”应执行相应控制，按账号实际音源权限播放。跨 Disc 边界仍沿用实体顺序。
7. **指定封面**：若有多张关联专辑，要求助手改用非默认专辑封面，它应说明工具限制，不能用默认封面代替。请求默认网易云封面时应展示真实来源及新旧封面，取消不改收藏。

提示词属于模型行为引导，不能代替后端授权检查。自动化测试验证工具流程、流式响应和界面确认约束；实际服务的语气、意图判断与工具选择仍需上述手动验收。
