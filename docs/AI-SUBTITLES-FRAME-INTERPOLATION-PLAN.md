# DiscAtelier 实时双语字幕与视频插帧可行性

研究基线为 0.5.0，日期为 2026-11-27。建议先做本地视频双语字幕，单独验证本地视频 GPU 插帧，最后扩大光盘覆盖。本页是规划和初测记录。

## 在播放器里怎样使用

在视频播放器提供两个独立选项。开启「AI 双语字幕」后，默认上行显示当前音轨的原文，下行显示简体中文。首轮以日语访谈和英语对白验收，提供源语言选择。原文先出现，译文随后补在同一条。对已有可靠文本字幕的本地影片，可直接按字幕时间翻译。DVD / 蓝光的位图字幕暂不纳入文字翻译入口。

「视频插帧」首轮只提供本地视频原帧率与实验性 2 倍。以 23.976→47.952、24→48、30→60 作测试。播放时长、音高和进度条保持一致。字幕和菜单在插帧后合成。高刷、60 Hz 与混合显卡输出分别检查实际显示节奏。

## 项目接入点

- 本地文件由 `apps/desktop/src-tauri/src/playback.rs` 启动 VLC，后端会话封装在同目录的 `playback_backend.rs`。蓝光 0.5.0 走 VLC 菜单，现有 mpv 嵌入窗口失败记录见 [蓝光播放说明](BLU-RAY-PLAYBACK.md)。本地实验播放路径切换前，须通过内嵌、全屏、切音轨和退出回归。
- `spectrum.rs` 从默认输出设备回环采集，只向界面发送频段值。对本地文件优先验证按当前音轨独立解码 PCM，向前读取少量音频，以媒体时间安排字幕，静音仍可识别。读取器必须跟随音轨、起点、倍速和跳转。光盘试验 Windows 进程树回环，现有播放会话只读取光驱一次。该接口需 Windows build 20348 及以上；进程捕获仍可能混入应用自身其他声音，并受输出模式影响。捕获失败需提示，保持影片继续播放。[微软进程回环样例](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)
- `video_surface.rs` 管理独立的原生子窗口。第一步用固定的中日两行文字测试 VLC 自身叠字，检查多行、字体、原有字幕共存、全屏、菜单切换。若文字排版不足，再试专用透明原生字幕层，验证鼠标穿透和焦点。避免逐帧经 WebView/IPC 搬运像素。[libVLC 播放器 API](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html)

## 听译路线

1. 第一条链路采用分声道解码/混音、重采样、语音活动检测、分段转写、按句翻译、两行显示。5.1 需比较中置声道与常规下混的人声质量。用有上限的后台队列运行，停止或切片时取消任务。用会话、音轨、播放时间和跳转代次关联结果，丢弃旧代次或过期结果。暂停冻结字幕，不积压翻译。
2. 本地方案先试 whisper.cpp 多语言模型，按需下载。Whisper 原生翻译目标是英语；日语→中文要额外的文本翻译引擎。可先接用户已配置、具备翻译能力的文本服务，仅发送已确认的原文与少量上下文。完全离线则另测本地翻译模型、权重许可、安装体积和显存。[whisper.cpp](https://github.com/ggml-org/whisper.cpp) · [Whisper 模型说明](https://github.com/openai/whisper)
3. 云端替代可用 Azure Speech Translation 同时取识别文本和译文。需要适配连续会话、重连、凭据和用量提示；首次开启时明确音频将发送至服务商。按区域和用量核算费用。默认不落盘音频，文本缓存或字幕导出由用户选择。[Azure Speech Translation](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-translate-speech)
4. 光盘真实回环只能听到已播出的台词，译文必然晚于声音；本地文件可以预读，避免把同一延迟承诺用于两者。纯音乐、歌词、多人抢话、角色名、专有名词和强背景音乐分别评估，先交付对白听译。

## 插帧路线与初测

本机 Windows 11 build 26200，i9-13900HX、Intel UHD + RTX 4060 Laptop（8188 MiB）。项目附带 mpv v0.41.0-244，运行时列出 minterpolate、VapourSynth、D3D11 视频处理滤镜；VLC 3.0.22 附带 marq 插件。滤镜存在只证明可调用。

用随包 mpv 对 2 秒 1280×720、24 fps 的 FFmpeg testsrc2 合成片做单次无声、无显示、无节流全片处理。基线 0.25 秒，默认运动估计 minterpolate 输出 48 fps 耗时 8.82 秒，两次均正常读到片尾。耗时含启动，当前这组参数约用 4.4 秒处理 1 秒画面，不能作为默认实时方案。此结果不衡量 GPU RIFE 或实际影片画质。

测试参数：`--no-config --vo=null --ao=null --untimed --no-audio`，输入 `av://lavfi:testsrc2=size=1280x720:rate=24:duration=2`，对比 `--vf=null` 与 `--vf=lavfi-minterpolate=fps=48`。

先用 GPU RIFE 对相邻帧做 2 倍插帧，再在内嵌窗口验证解码→推理→显示全链路。上游 ncnn/Vulkan 示例以图像对或序列为输入，播放器集成需要内存帧接口、时间戳、声音主时钟与取消机制。可对比随包 mpv 的 VapourSynth 桥接路线和专用渲染路径，记录 GPU↔CPU 拷贝成本。mpv 的常规 interpolation 主要处理片源与显示器刷新率不匹配，可另列为平滑播放。libVLC 3 自定义内存帧回调有额外拷贝和硬解限制。摄像机切镜、动画停格、字幕边缘、舞台灯光均需人工看片；切镜直接显示原帧，持续超预算则退回原帧率。分发前确认运行库、模型权重及依赖的许可。[RIFE ncnn Vulkan](https://github.com/nihui/rife-ncnn-vulkan) · [mpv 手册](https://mpv.io/manual/stable/) · [libVLC 视频回调](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html)

## 建议验收顺序

| 阶段 | 决定是否进入下一阶段的实测 |
| --- | --- |
| 本地双语字幕 | 固定双行叠字通过后，用有参考字幕的日语、英语对白各测 10 分钟。记录原文错误、错译/漏译、断句，以及从句尾到原文/译文出现的 P50/P95。首轮建议译文 P95 ≤3 秒，播放、静音、跳转、换轨后无串句，断网仍能正常观看。 |
| 实体盘听译 | DVD 和蓝光各测试正片、菜单、章节跳转和音轨切换。其他程序同时播放语音时不应被识别；设备切换、静音和无法捕获要有明确结果。 |
| 本地 GPU 插帧 | 先测 720p，再测 1080p SDR，分别记录原速与 2 倍的输出帧时间、丢帧、音画偏差、GPU/显存和功耗。建议 1080p24→48 连播 10 分钟，输出丢帧低于 1%、音画偏差不持续超过 80 ms。AI 字幕与插帧同时开启后重新测量。 |
| 发布范围 | 每种来源独立验收。4K/HDR、隔行素材与实体盘插帧另行验证色彩、去隔行、菜单高亮和鼠标坐标。原型未通过时保留默认播放路径，两功能均可独立关闭。 |
