# 验证、迭代与交付

## 四层验收不能互相代替

| 层 | 必须取得的证据 | 不足以证明 |
|---|---|---|
| 文件 | 最终包 SHA-256、字节数、版本，真实 JS 校验通过、所有图片解码和预算通过 | 仅扩展名正确、仅 JSON.parse 成功 |
| 渲染／动作 | 从导出的包加载全部资源，真实点击可见表面，正常速度取出／收回／翻页，正反面与边缘截图，无缺图或脚本错误 | 制作源预览、只调用动作或父节点 id、只有状态末端断言或内存替代纹理 |
| 目标应用 | 用户实际 DiscAtelier 版本；上传模型、保存版本、返回再打开；拆装／放回／全部收起成功 | 快照浏览器预览、AtelierPublisher 网页导入 |
| 用户认可 | 用户明确认可当前修订的结构、贴图、材质和操作 | 没回复、只给出某个尺寸、脚本全部通过 |

### 文件与渲染

1. 运行 `node scripts/validate-package.mjs <包>` 与 `python scripts/validate-images.py <包>`。预检失败修复导出源，不绕过校验器。随附工具使用工作区 runtime；若目标安装版不同，另按该目标的实际校验入口验证。
2. 本地预览页面通过“载入模型包”载入最终文件；开发源与最终包应同样呈现。检查所有纹理已嵌入且无外部请求，透明叠层、折痕、轮廓、标签四边、文字与比例均符合素材。
3. 旋转检查纸张、金属、塑封、丝绸：高光随角度变化，印刷不随高光丢失。查看近景及全景。实际反射无法准确分离时向用户提出具体取舍，不声称完美复原。
4. 测各部件及其依赖，多次取回、收回、中途关闭、从多个状态全部收起。检查路径不穿模、动作边界不跳跃、再次打开不丢部件。
5. 在正常速度下，用户手动旋转／平移／缩放后连续翻正反页，采样相机位置、up、target、zoom 和可见性。翻页前中后应保持；进入阅读的一次取景单独判断。退出单件查看应恢复进入前视角。

### 真实点击回归

对新增或修改的操作，从用户能看到的表面进行真实指针点击，检查实际命中、状态变化和可见结果。可将已知表面点投影到画布后用鼠标点击，但不能调用 `pick(parentId)` 或动作函数替代这一层。其他状态遍历仍可调用动作，二者分开记录。

最少覆盖本次涉及的收纳、取出后、放回后再次取出三种情形；透明层和可点击子部件是重点。翻页测试包括左右页的实际命中，不只点封面。用户报告“点了没反应”时，先保留失败状态和命中路径，用同一操作在修复后验证，避免只证明动作函数能执行。

### 长册图像与几何复核

全册建立来自最终纹理的总览，逐页检查页序、缺面及明显杂边；书脊、四角、分切线、补手区域和跨页接缝做近景检查。抽样测试交互不能替代全部页面的图像复核。曲边与修补处理方法见 [页面边界与书册](paper-pages.md)。

穿模检查覆盖动作中段，并记录测试对象、采样方式及豁免的真实装订接触。页片层序、开合前后顶面身份、物品最大展开占地分别验，不以“最终状态没报错”概括所有几何质量。

### 目标 DiscAtelier

在用户许可的测试收藏或隔离数据环境验收，避免覆盖真实版本模型。0.2.3 的常规路径为新增收藏或“编辑版本 → 上传模型 → 保存”，随后打开收藏详情。以实际 UI 为准，不能只按标题猜接口或直接写 SQLite。

有原生环境且获得测试授权时走真实选择文件／校验／保存／重开。只能操作独立网页时，明确应用导入未验证；让用户在其已安装版本选择你提供的最终包并报告结果。导入失败索取完整错误和软件版本，回到格式／图片／结构校验定位；不要求用户关掉验证。

不要为了使用测试目录而随意设置猜测的环境变量。若用仓库 harness，先读其真实代码；普通 Release 可能不编译测试分支。不得覆盖个人收藏数据库或密钥。

### 向用户交付可检视的修订

提供实际包和能直接打开的预览，说明本次改动、已验证项目、仍需确认项目。每次用户反馈对应到部件、原图、几何或动作，修正后重新导出；再次核对 hash 与预览，不打开旧标签页冒充新版本。

交付以一个确定的包为准：导出后记录哈希，使用该文件做校验和目标应用测试，复制到交付目录后核对相同哈希，再从交付目录自己的启动入口实测。核对页面真正请求的模型文件及运行依赖；地址中的修订参数只用于辨认／刷新，不证明载入了新包。复制时保留相对路径，历史包不能因同名文件展平覆盖当前包。

再次导出产生不同哈希时，旧报告保留原哈希，不能只改报告中的哈希充当重测。说明本次变化并补受影响验证；未变的几何／图像可凭可核查的内容一致性复用历史证据，最终入口点击、包校验和真实导入须对应交付文件。测试运行库、制作预览和交付播放器不一致时分别核对，不能以其中一个通过推定全部通过。

若目标只具备某项新格式的隔离程序且仅该程序通过导入，交付说明必须给出该程序的确切版本或构建标识，明确旧正式版是否支持、正式版是否已替换；不得写成用户原安装版本已兼容。

用户尚未验收时写“模型包已制作，待用户验收”；未做应用导入时写“预检通过，待目标程序导入”。收到具体认可后记录所对应的最终哈希与修订。用户之后修改要求会重新打开受影响验收项。

保留用户反馈的原意。“马马虎虎”“先这样”等有限接受不改写成“用户完全满意”，也不因为这类反馈而自动继续用户没有要求的重做；记录程度与已知不足，按下一条请求继续。

## 交付内容

原图目录／用户指定目录下 `模型/`：

- `<实际id>.ateliermodel`：正式可导入的数据包。
- 独立预览、运行依赖、本地启动脚本；使用本机地址，不能依赖作者磁盘或开发服务器。Windows 可提供 `打开预览.cmd`，其他系统给 Python 启动命令。
- 制作源及处理后贴图，照片到贴图的映射；原照片和旧包保留。
- `说明.md`：专辑及作者、格式版本、目标软件版本、操作方式、比例单位、目录、已授权估计及已知限制。
- `验收.md`：最终 hash、包大小、校验命令与结果、实际应用版本及测试结果、用户认可记录。不能把模板文字填成通过。

在全部四层完成后，才以“完成”交付。无法取得必要素材或验收反馈时，把可用成果保存在明确位置，列出准确的待补项，不无限等待、不编造验收。
