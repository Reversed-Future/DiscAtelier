# 验证与导入

<p class="lead">能解析、能渲染、能保存、符合实物，是四件不同的事。</p>

## 四层验证 {#layers}

<table><thead><tr><th>层级</th><th>所需证据</th></tr></thead><tbody><tr><td>文件</td><td>真实结构校验、全部图片解码、预算、最终 SHA-256。</td></tr><tr><td>渲染与动作</td><td>重新加载最终导出包，正常速度检查所有部件与动作。</td></tr><tr><td>目标应用</td><td>实际 DiscAtelier 版本，上传、保存、退出详情、重新打开。</td></tr><tr><td>实物与作者认可</td><td>尺寸、贴图、材质和操作与实物对照，记录具体修订的认可。</td></tr></tbody></table>

## 文件预检 {#preflight}


```text
node scripts/validate-package.mjs example-hinge.ateliermodel
python scripts/validate-images.py example-hinge.ateliermodel
```


路径从解压后的入门包目录运行。换成你实际导出的文件名；空格路径用引号包住。不要把上次导出的哈希贴到新版本验收记录中。Node 结构检查不会解码图片，Pillow 检查也不能替代 Rust 入库校验。


## 浏览器检查 {#visual}

<ol><li>用“载入模型包”读最终文件，确认无外链资源、缺图或控制台错误。</li><li>旋转查看正面、背面、侧边、内部；确认文字方向和透明层。</li><li>依次取出与独立收回，再从不同状态“全部收起”。</li><li>正常速度观察中途路径、相机与遮挡；不要只看起点终点。</li><li>进入阅读后调整相机，连续前后翻页，确认视角不被重置。</li></ol>

## 应用内导入 {#native}


使用测试收藏或明确允许修改的版本。进入新增收藏或“编辑版本 → 上传模型”，选择最终 .ateliermodel，确认模型标题并保存。退出详情后重新打开，再测试拆装、单件返回、全部收起及返回收藏架。


应用包含两层检查：Worker 执行完整 JS 模型校验，Rust 检查原生存储边界、图片真实解码与主要引用。两层职责不同；不要直接写 SQLite，也不要为绕过错误改坏格式字段。


模型与版本保存属于同一事务；模型不替代收藏封面和购入资料。测试仍应使用可控记录，避免覆盖真实收藏的模型。


## 验收记录模板 {#evidence}


```text
模型文件：
修订／SHA-256：
模型格式：
目标 DiscAtelier 版本：
结构预检命令与结果：
图片解码结果与总像素：
导出包重新载入／正常速度动作：
应用上传／保存／重开：
实物对照与作者认可：
已知限制／未完成检查：
```


未做的项目写“未验证”。每次修正模型后更新文件哈希，并重新检查受影响的动作；在实际应用中保存、重开后再记录导入结果。
