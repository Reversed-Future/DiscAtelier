## 实现

- 原生导入、保存及备份恢复接受 v3；核对结构白名单、运行版本、图片和贴图引用、装配数据字段、纸边／挂孔／解密数据及大小限制。原有 50 MiB 文件、192 Mi 像素总预算保持不变，六份实际包均在限额内。
- Worker 使用上游 v3 解析器。模型只提供数据，未知结构或运行版本被拒绝；脚本和模块地址不会进入解析结果。结构程序是随应用编译的固定代码。
- 六种结构按需加载；浏览收藏架仍只读封面，进入详情才创建一个 WebGL 画布。独立图片最多四张并发读取，保留原纹理和材质参数；取消时等待已启动解码完成并释放，动画也停止。
- 部件选择、查看、取放、翻页、解密等操作由 React 在现有黑白控件中呈现，动作来自实际会话状态。按原装配顺序全部收起，初始／收起后使用正视取景，沿用完整首帧准备与封面淡切。
- 来源文件哈希记录在 `packages/atelier-model-runtime/upstream.json`；只引入运行所需 JavaScript，不复制模型包、照片、账号数据或源项目服务。

## 验证边界

本轮结果：67 项脚本测试、145 项 Rust 测试、严格 Clippy、TypeScript／Vite 和 Tauri Release 预览构建通过。Rust 默认跳过 7 项外部环境／专项检查，其中六份实际 V3 包校验本轮显式运行通过，另外计数。日志保存在 `artifacts/model-v3/`。

完整回归的前两次构建被 Windows 拒绝执行 `vswhom-sys` 的构建程序（错误 5），文件存在且有执行权限，未查到 Defender 记录；用户要求重试后，原配置的完整回归及严格检查通过。未修改防护设置，不能据此判断先前错误的具体来源。

脚本回归覆盖六套结构注册表一致性、非法资源／版本拒绝、并发加载取消、动画取消。隔离 SQLite 检查 v3 准备快照、入库、备份、恢复后的原包一致性。

`scripts/verify-model-v3.mjs <模型包目录>` 只读实际文件，六套 V3 使用真实 Three 几何及会话检查取出、归位和四套歌词本连续翻页的视角／可见性；同时解析目录中现有 V2/V3 模型。此检查使用内存纹理代替 GPU 上传，不能证明实际渲染效果。Rust 另行完整解码六份实际包的内置图片。没有启动浏览器、桌面程序或操作个人数据库。

## 手动测试

1. 退出现有程序，打开本轮构建的 `target/release/DiscAtelier-model-v3-preview.exe`，保留同目录运行资源。
2. 进入收藏的“编辑版本 → 上传模型”，选择对应 `.ateliermodel`，确认标题并保存，再进入详情。
3. 点击部件或底部操作：验证取出、查看、放回及“全部收起”；返回收藏架再打开。加载时可返回，之后应能再次正常打开。
4. 四套带歌词本结构取出歌词本后，手动旋转／缩放，再连续上一页、下一页，观察视角是否保持；《研究》测试歌词卡与解密操作，《雷雨季电台》测试外盒、内托和磁带盒。
5. 打开一个原有 V2 收藏，核对拆装、封面淡切和退出。实际画面、窗口动效和显卡效果以此轮手动测试为准。
