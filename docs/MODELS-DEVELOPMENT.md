# AtelierPublisher 模型接入

2026-10-22：新增六种固定装配 V3 模型兼容，继续支持 V2；导入方式不变，详情新增对应部件与动作控件。格式边界、验证和手动测试见 [V3 兼容说明](MODEL-V3.md)。下文 V2 专项记录保留历史背景。

2026-10-20 最新：陈列只显示封面，点击取出后才加载模型，首帧完成后 180 ms 淡切；放回时淡切回封面并释放画布。模型初始状态和复位采用封面正视角，原材质、光照和拆装轨迹保留。见[当前验收](MODEL-ON-DEMAND-VALIDATION.md)。之前的截图缓存已退出展示流程，其[历史验收](MODEL-PREVIEW-VALIDATION.md)不代表当前交互。

静态封面与包内预览使用独立的已解码图片缓存，最多 12 项／估算 64 MiB（URL UTF-16 字节数与 RGBA 像素之和，不是进程内存保证）。当前项和相邻项重新挂载时同步取图，不再短暂退回文字占位。首读等待与缺图是不同状态。陈列扩大的模型容器仅用于绘制，不接收鼠标；Esc 恢复焦点但不画封面外框。

## 使用

添加收藏或编辑版本时选择“上传模型”，导入 AtelierPublisher 导出的 **v2 或受支持结构的 v3 `.ateliermodel`** 文件。已有模型时显示标题、更换和移除。版本名称、作者、载体与购买资料仍由收藏表单管理，不从模型名称推断发行资料。

收藏页及整理表格显示本地封面；没有封面时使用模型包内置预览。取出后才加载真实模型，可拖动旋转、滚轮缩放、点击部件执行模型自身的动作；方向键旋转、加减键缩放，Ctrl 组合键仍调整应用缩放。单件收回和全部收起采用原模型路径；“放回”先收起模型，再淡切回封面并关闭详情。按钮只在当前状态需要时出现。

没有模型时使用原封面，没有封面时使用默认外观。移除模型保留封面。加载失败或显卡上下文丢失时恢复封面；重新打开可重试。Discogs 自动封面和模型独立保存，同版多套共享版本模型。

## 边界

- 当前支持 `atelier-interactive-model` **version 2**，Z 轴向上，使用现有导出器的精确字段和节点标识。v1 专用 rig、OBJ、GLB、FBX 不直接导入。
- 文件 ≤50 MiB；仅内置 PNG/WebP，单张图片边长 ≤8192、单张编码字符串 ≤16 MiB，封面与贴图合计 ≤192 × 1024² 像素。实际最大样本《把他的蜡笔拿走！》合计 176,601,152 像素；提高总预算以接纳原图，保留单图尺寸、解码和文件限额。
- 完整上游几何、材质、引用、动画和状态图校验在一次性 Worker 中运行，成功后才渲染。Rust 独立检查文件限额、包头、图片实际解码、表大小、层级循环、主要引用和状态；两层职责不同，不宣称 Rust 重写了完整动画校验器。
- 模型是数据，不执行模型附带代码，也不请求远程贴图。模型查看不需要 AtelierPublisher 服务器运行，不修改其源文件。
- 已完成当前 10 份 v2 模型的状态图兼容矩阵、代表性原时长拆装／连续翻页、竖放陈列与共享物体取放。自定义陈列姿态编辑、万级收藏和长期 GPU／内存稳定性仍待专项验收。全状态遍历使用减少动态模式，不等于逐帧审查所有动作组合。

## 分层

| 层 | 实现 |
| --- | --- |
| 独立运行库 | `packages/atelier-model-runtime`；对外只有解析与挂载端口，运行时不导入兄弟项目 |
| 来源记录 | `upstream.json` 保存原始文件 SHA-256；保留 Three.js MIT 许可；不打包用户唱片模型 |
| 上传与校验 | `src/models/ModelField.tsx`、`assets.ts`、`validation.worker.ts` |
| 展示 | `ModelView.tsx`、`ModelPreview.tsx`；React 管理黑白 MiSans 操作按钮 |
| 用例与 IPC | LibraryRepository／LibraryService 的模型读取端口；创建、Discogs 导入和版本编辑携带独立模型字段 |
| 持久化 | schema 4 的 `model_assets` 和 `editions.model_asset_id`，完整 UTF-8 包和预览按 SHA-256 去重 |
| 恢复 | 校验模型哈希、字节数、原包与预览／标题一致性，然后才替换现用库 |

新内部字段 `model`、`modelAssetId`、`modelTitle`、`ModelChange` 属于 DiscAtelier IPC，不是对 AtelierPublisher 字段的推测。模型变更与版本保存处于同一 SQLite 事务，沿用请求幂等和 revision 冲突保护。schema 3 升级前备份，旧备份恢复时先迁移。

只有取出检视的模型使用一个 WebGL 画布。`useCollectionArtwork` 用稳定的 React portal 容器在架位与详情之间移动封面；进入详情时挂载模型，等待首帧就绪且位移结束后淡切。关闭前按原模型路径收纳并恢复正视角，返回过程中淡切回封面，到位后释放画布。打开途中返回从当时的位置反向移动，弹窗在物体归位后才卸载。`artwork-motion.ts` 负责可中断的位移，默认 280 ms 取出、260 ms 放回，减少动态模式直接完成。

返回陈列、打开设置或编辑、切换收藏时，取消旧 Worker 和动作并释放几何、材质、纹理、环境贴图、控制器及渲染上下文。陈列不创建 WebGL；只缓存最近一个已解析模型，重复取出仍重新建立渲染场景，避免后台长期占用 GPU。模型运行库按需加载。显卡上下文丢失后保留封面，下次取出可重试。

陈列按用户反馈恢复原有中央放大、两侧后退缩小及变暗的布局，保留静态阴影，移除横向架面。材质、贴图、灯光、2048 阴影图和像素比上限保留；不修改模型作者的节点姿态与动作轨迹。共享物体的 CSS 缩放不参与画布分辨率计算，进入详情时按布局尺寸更新绘制缓冲区，避免移动中的缩放导致画面模糊。没有独立封面时，模型加载期间显示包内预览，避免只显示默认文字盒。

### 首次显示与加载衔接

已入库模型通过只读 `collection-model` 本地协议直接进入 Worker，省去全文经 IPC 到主线程再转发的路径。数据库读取运行在 Rust 后台线程；协议仅接受主窗口、本地来源、GET 和 64 位十六进制资产标识，拒绝查询参数和任意文件路径。Worker 保留完整上游校验。

同一模型的并发读取共用任务，各调用可独立取消；最后一个调用取消时终止 Worker。完成缓存只保留一个模型，失败／取消结果不进入缓存，后续可以重试。底层已开始的 SQLite 读取不强行中断，但其结果不会继续解析或替换界面。

贴图使用原 TextureLoader，最多四张同时加载；贴图属性与各向异性保持原值。取消或失败后等待已启动任务结束并释放纹理，后续任务不再启动。画布在贴图加载期间也能随取消释放。动作轨迹、材质效果和阅读取景保留；本轮只调整总览取景、检视开关及收纳后的陈列视角恢复。

首帧之前准备主画面、透射通道的着色器和参数信息；临时 1×1 渲染目标仅用于匹配编译环境，不绘制模型、不替代实际分辨率。`prepare-renderer.js` 的变体准备依据当前固定 Three 源码的 `renderTransmissionPass`，升级 Three 时需重新核对该契约及 `renderer.info.programs` 的程序接口。

当前 Three 已移除 `PCFSoftShadowMap`，旧版会在首次绘制时自动替换成 `PCFShadowMap`。现在提前使用其实际采用的 `PCFShadowMap`，避免提前编译的材质在首帧失效；2048 阴影尺寸、偏移、光照、材质和实际阴影算法均不变。保留 Three 原有着色器错误检查，未采用关闭诊断的实验改动。

`mountModel` 先绘制完整首帧再返回。封面始终保留在底层，模型首帧就绪后用 180 ms 的 opacity 交叉淡入，返回时反向淡切；减少动态模式关闭该渐变。加载中的画布不能取得键盘焦点；切换资产更换会话，返回后中止任务并释放场景。

模型存入 SQLite 是本阶段确保事务和自包含备份的明确选择；旧模型资产暂保留，与现有封面策略一致。大量大型模型会增加数据库、备份和内存开销，后续可通过资产端口迁移至文件存储，不能把当前实现等同于大规模资产管理完成。

## 验证

### 原生文件读取与分段计时

模型选择通过 Windows 文件选择器完成，Rust 在后台线程中限长读取 UTF-8 文件、校验并计算 SHA-256。已校验的原始数据保存为不可变内存快照；前端仅持有新定义的 `ModelPreparation`（`token`、`title`、`byteLength`）。前端完整校验仍使用原有 Worker，通过 `prepared-model` 本地协议读取快照，不再将整包 JSON 放入表单状态或保存请求。

`modelToken` 用于新建／Discogs 入库，`ModelChange::Prepared { token }` 用于版本编辑。这些均为 DiscAtelier 内部契约。保存事务复用快照，不重复图片解码或模型哈希；版本修订号、事务原子性和幂等回执照常验证。原文件在选中后发生变化不影响已校验快照。旧文本 IPC 保留兼容，但正常 UI 走原生读取路径。

快照最多保留两份，30 分钟过期，替换或关闭表单时释放；跨“版本／购入”步骤由父表单持有。取消选择不会写入数据库。协议只接受主 WebView、明确本地来源、GET 和 UUID 引用，不接受文件路径，不缓存响应。

`DISCATELIER_PROFILE_LOG` 可开启原生 NDJSON 分段计时，仅记录阶段、毫秒及线程，不记录路径、模型或购入资料。前端 Performance measures 记录文件准备、Worker 校验、请求编码、保存以及模型读取／解析／挂载。计时为嵌套区间，不能把总计和内部阶段相加。

自动测试使用 Debug 或显式 `performance-harness` 构建、隔离数据目录内的 `model-selection.txt` 替代人工选择文件，后续读取／校验／保存与正式流程相同；空文件模拟取消。普通 Release 不编译该分支，也不采用测试数据库环境变量。

`crates/storage-sqlite/tests/models.rs` 验证共享、幂等、revision、移除、恢复、重启、恶意／超限输入和损坏备份拒绝。测试目录保留，不递归清理。

`scripts/verify-models.mjs` 在隔离 Tauri 数据目录中加载 AtelierPublisher 的现有翻盖盒、抽屉盒和完整唱片包，验证上传与真实渲染、回退、拆装、恢复、上下文丢失、快速关闭和最小窗口 200%。测试读取现有模型包，不将模型复制进分发源码。具体通过记录见 ROADMAP。

`scripts/verify-native-picker.mjs` 配合 Windows 原生 UI 操作，覆盖实际文件窗口的取消、中文与空格路径、损坏重试和更换。当前点击加载与双向淡切使用 `scripts/verify-model-on-demand.mjs` 验证。`scripts/verify-model-loading.mjs`、`scripts/verify-model-preview.mjs`、`scripts/benchmark-model-display.mjs` 保留此前自动加载流程的历史脚本，不适用于新的按需加载流程。

`scripts/verify-model-matrix.mjs` 从真实模型包读取状态、点击、收回和重置契约，遍历所有可达状态及转换，验证单件检视与最终姿态／视角。`scripts/verify-shelf.mjs` 为旧版常驻画布流程，历史验收见 `MODEL-SHELF-VALIDATION.md`。本轮只在默认比例验收，不重复 200% 缩放。
