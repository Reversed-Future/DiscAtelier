# 蓝光播放：菜单、AACS 与整片分段进度

2026-11-27，开发预览，未发布。

## 一个播放列表就是一部影片

蓝光电影的常见结构是**整部电影一个 `MPLS` 播放列表**，列表内部再由多个 `M2TS` 片段组成；其余 `MPLS` 往往是预告、宣传片、花絮或菜单背景，不是电影的分段。因此本版：

- 不把多个 `.mpls` 拼接成一部影片；
- 不自动循环播放宣传片；
- 不把所有播放列表当作连续剧集。

电影和花絮仍由“播放列表”下拉框区分；只有用户选择的那一个播放列表会用于分段元数据。

## 当前支持路径：光盘菜单

本轮实机排查确认，当前 Windows 构建下最可靠的蓝光入口是**光盘菜单**：

1. `bluray:///F:/` + `:bluray-menu=1` 交给 VLC 的 libbluray。
2. 启动前先把内嵌原生视频区域显示为可见窗口，避免从隐藏的 1×1 HWND 启动。
3. 进入光盘菜单后，由用户选择正片、花絮或音轨。

**“直接播放”按钮已移除**，只要请求具体 `.mpls`，播放层会改走 `bd-menu`。原因不是菜单不可用，而是 MPV 的嵌入窗口路径在本机创建失败：

- MPV 以 `--wid=<DiscAtelierVideoSurface>` 启动时，`gpu`/`gpu-next`/`direct3d` 都报 `unable to create window`；
- 不传 `--wid` 时 MPV 可以播放，但会创建独立窗口，无法嵌入当前播放界面；
- VLC 的直接 access 会从 First Play/顶部菜单开始，不能可靠地按 `.mpls` 选择正片。

因此本版优先保证“能进菜单、能选正片”，不再用 MPV 的异常退出冒充直接播放。MPV 独立窗口重嵌入是后续单独工作，不在本预览中宣称完成。

## AACS 库为什么之前找不到

VLC 的 libbluray 插件使用 **msvcrt.dll**，而 Rust 的 `std::env::set_var` 只更新 Win32 环境块；libbluray 的 C `getenv()` 读不到进程启动后设置的 `LIBAACS_PATH`。这导致同一张已插入、已能识别菜单的光盘仍报：

```text
This Blu-ray Disc needs a library for AACS decoding,
and your system does not have it.
```

修复方式：

- 去掉 `resource_dir()` 返回路径的 `\\?\` 前缀；
- 用 `_wputenv_s` 同时写入 **ucrtbase** 和 **msvcrt** 两套 CRT 环境；
- 对 `LIBAACS_PATH`、`LIBBDPLUS_PATH`、`LIBBLURAY_CP`、`JAVA_HOME`、`VLC_PLUGIN_PATH` 都这样发布；
- 逐进程给 MPV 的 `Command` 设置 AACS 路径，避免依赖父进程环境。

修复后，同一张 AACS 光盘的菜单可以正常进入并播放。

## 菜单返回与错误

VLC 在菜单背景输入提前结束时可能进入 `Stopped`。现在：

- 菜单启动后 90 秒内反复结束时，最多重新打开 3 次；
- 重新打开前先停止旧输入，再重新播放；
- 3 次后仍未稳定，返回明确错误（提示改用菜单或检查 VLC/Java）；
- 正常电影结束不进入菜单重开流程，不循环电影。

## 分段元数据与完整进度条

光驱页以只读方式解析 `BDMV/PLAYLIST/*.mpls`：

- `PlayItem` 的 `in_time`/`out_time` 是 45 kHz 时钟；
- 每段时长 `(out_time - in_time) / 45000`；
- 总时长是所选播放列表内所有片段时长之和；
- `connection_condition` 5/6 标记为无缝；
- 章节标记也解析，但当前蓝光进度条画的是 `PlayItem` 分段，不是章节。

首次显示蓝光时默认选择时长最长的播放列表；下拉框显示 `文件名 · 完整时长 · 段数`。如果正片播放列表只有一个 `PlayItem`，分段数就是 1，进度条不会人为切分。

从菜单进入正片后，当播放器报告的完整时长超过 300 秒，控制条会用**最长播放列表**的分段元数据绘制完整进度条；菜单画面本身保持普通进度条。这个路径不拼接宣传片。

## 自动菜单识别

设置 → 助手 →「自动识别光盘菜单」控制是否自动识别，默认开启。开启后打开光驱面板，只要检测到未关联的 DVD/Blu-ray、已配置图片 AI，且当前没有播放或识别任务，就会自动开始一次菜单识别；关闭后只能手动点“识别菜单”。

- 同一媒体 token 在一次应用运行内只自动尝试一次；
- 已关联媒体不自动识别；
- 识别不是从元数据“猜”菜单，而是打开一个**静音、不可见的 VLC 菜单会话**并截取一帧；因此截图阶段仍要占用光驱约 12 秒，无法完全避免读取/解码；
- 截图完成后 VLC 会话立即释放，AI 请求在后台继续；此时“菜单播放”已经可用，不必等 AI 最长 120 秒；
- 播放中不抢占光驱；失败原因保留，可手动“重新识别”。

## 光驱面板布局

面板加宽到 780 px，`播放列表 / 分段 / 时长 / 区域 / AACS / BD+ / BD-J` 每项整体单行显示；长值用省略号或 `title`。BD-J 只显示检测结果，Java 说明放在下方提示。播放列表下拉框保留用于查看时长/分段和“检查播放”，不再承担直接播放。

## 关于 BD-J 的实测结果

这张用户样盘的 `BDMV/JAR` 目录存在，光驱页会显示“BD-J 检测到”，但 VLC/libbluray 实际报告：

```text
HDMV Titles: 14, BD-J Titles: 0, Other: 0
```

说明**目录存在不等于该盘使用 BD-J 菜单**；本盘实际按 HDMV 菜单播放。AACS 修复后菜单可进入。不能仅凭 `JAR` 目录宣称 BD-J 已支持。

## 音轨标签

旧的音轨下拉框直接显示 VLC 的裸 ID 和通用名：

```text
4352 · 轨道 1 - [日语]
```

现在从 libVLC 的媒体轨道表读取 `psz_language`、`psz_description`、音频 codec 和
`i_channels`，再与 VLC 的音频轨道描述按 PID 或音频顺序合并。当前菜单音轨会显示为：

```text
日语 · 2.0 立体声 · DTS
```

正片播放列表还会解析 `MPLS` 的 STN 表，一次取得所有主音轨的 PID、语言、coding type 和 format，所以四条音轨在**切换之前**就能显示声道和格式，不需要先选中再加载：

```text
日语 · 5.1 环绕 · DTS-HD MA · 音轨 1
日语 · 2.0 立体声 · DTS-HD MA · 音轨 2
日语 · 5.1 环绕 · DTS-HD MA · 音轨 3
日语 · 2.0 立体声 · DTS-HD MA · 音轨 4
```

两条 5.1 或两条 2.0 的标准标签相同时，用“音轨 N”保留盘的顺序；这不是作者写的“英語主題歌版”，只是可区分的序号。

只有一条音轨时，下拉框宽度跟随内容（`max-content`，190–420 px）；两条以上时使用紧凑的 **2×2 网格**，宽约 600 px，每格尽量单行，高度取内容高度、最高 180 px，不会把两行撑到整个控件区。VLC 有时会把正片音轨重新编号为 1–4，因此除了按 PID 合并 STN 外，还按轨道标题里的 `轨道 N` 和音频顺序回退匹配；声道布局以 STN 的 format 为准，因为 VLC 可能对非激活轨道报告输出端的 2 声道。

播放器的音轨下拉框是**当前标题**的音轨，不是整张盘的全局音轨。顶菜单本身通常只有一条 2.0 菜单音轨；设置页里列出的四条 5.1/2.0 是正片播放列表的音轨。进入正片后，VLC 才会切换到正片音轨列表；如果菜单阶段只看到一条 2.0，不代表正片的音轨丢失。

需要区分两类信息：

- **可以从蓝光/播放器元数据得到的**：语言代码（jpn/eng）、声道数/布局（2.0、5.1、7.1）、音频格式（DTS-HD MA、DTS、AC3、LPCM 等）。这些由 libVLC 的媒体轨道表提供。
- **不能可靠得到的**：设置菜单里的“英語主題歌版”“音声ガイド”等是菜单作者画在 IG 图形里的文字，不是标准音轨文本字段。libbluray 通常只给出语言和格式；只有个别盘在 `psz_description` 中带说明时才能显示。要精确取得这些名称，只能 OCR 菜单画面或解析 IG 图形，不能从音轨元数据直接读。

## 菜单键盘操作

菜单打开后，应用会把焦点交给原生视频画面，并采样方向键/Enter：

- `↑` `↓` `←` `→`：VLC 菜单导航；
- `Enter`：确认；
- `Esc`：返回；
- `Space`：暂停；
- `F`：全屏。

采样条件不再要求焦点落在视频子窗口，只要求主窗口在前台、菜单画面可见且启用；因为 WebView 控件或 VLC 的 video child 都可能持有焦点。这样点击菜单后不需要再精确点中某个区域。翻页按钮自身的 `auto_action_flag` 仍可能在选中时翻页，这是光盘菜单的设计。

## 全屏暂停与空格

全屏隐藏控制条后：

- 暂停状态按 `Space`：开始播放，但**不唤出**控制条；
- 播放状态按 `Space`：暂停，并唤出控制条。

原生视频按键回调和全局键盘监听都按 `paused` 分支处理；此前任何按键都会无条件 `chrome.wake()`，所以恢复播放时控制条会弹出。

## 主界面光驱按钮

插入光盘后，主界面右下角常驻一个 46 px 的圆形光驱按钮，位置是 `right: 146px`，音乐/播放列表按钮保持 `right: 86px`，因此光驱按钮在播放列表左侧。没有播放时点击打开光驱面板；正在播放视频光盘时点击返回播放界面。按钮依据原始 `optical_list` 的介质存在性，而不是“已关联收藏”状态，所以未关联的新盘也会出现。从光驱页启动播放时，关闭播放器会回到光驱页；从收藏页启动则回收藏页。

## 进度条匀速

旧 `useSmoothPosition` 在每次快照（约 100 ms）时重建动画锚点，并用误差修正项追赶位置；VLC 时间戳本身不均匀，导致进度条周期性加速、停顿。现在只保留一个持续的 `requestAnimationFrame` 时钟：

- 以最新快照为锚点线性前进；
- 锚点不落后于已显示位置，避免“停顿后追赶”；
- 只有 seek 超过 2.5 秒才允许显示时间跳变或倒退。
