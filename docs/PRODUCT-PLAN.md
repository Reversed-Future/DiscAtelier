# DiscAtelier 产品与技术方案

更新日期：2026 年 10 月 20 日。产品定位为本地优先的个人实体收藏软件。主流程是找到准确版本、记录一件实物、在架上浏览、插盘后播放；网络资料、模型、播放器和 AI 都是可替换能力。

本方案中的内部类型、目录和方法名是新项目的明确设计定义，不代表外部 API 已存在同名字段。外部映射以已读取源码、官方文档和后续响应样本为准。

## 1 产品边界

| 能力 | 目标行为 | 交付阶段 |
| --- | --- | --- |
| 收藏 | 手动建档、条码和品番检索、版本选择、批量扫描队列 | 0.1–0.2 |
| 版本 | 同作品多国版、再版、限定版、多载体套装、同版多副本 | 0.1–0.2 |
| 购买 | 想购入、在途、已购入，日期、价格、币种、店铺、网址 | 0.1 |
| 展示 | 音乐与影像分区，竖放架、封面网格、表格，模型详情 | 0.1–0.3 |
| 音乐资料 | Discogs 为发行主来源，网易云补歌曲资料与可用播放地址 | 0.2–0.4 |
| 视频资料 | 手动录入，预留数据源接口，不预设供应商 | 0.1；自动来源待定 |
| 光驱 | 多设备、热插拔、插盘识别、人工绑定、播放入口 | 0.4 |
| 播放 | 音频 CD、支持的 DVD/BD、本地媒体、可用网络音源 | 0.4–0.5 |
| 助手 | 检索、补资料、整理、执行经授权的库操作 | 0.6 |
| 购物网页 | 先存链接；后续按站点适配价格与可用性 | 0.8，非首发 |
| 维护 | 本地备份恢复、签名更新、私有 GitHub 发布 | 0.1–0.7 |

平台优先级：依据当前工作环境，首版面向 Windows x64；macOS、Linux 保留端口设计，不能把 Windows 光驱实现包装成已跨平台。ARM64 需单独构建及验证原生播放器依赖。

## 2 需要保持清楚的五个概念

1. **作品**：专辑、电影或演出本身，负责聚合同一作品的不同版本。
2. **发行版本**：某地区、厂牌、品番、包装、载体组合的具体发行。Discogs release 对应此层；master 只帮助聚合，不代替版本。
3. **实物副本**：用户持有或正在购买的一套。相同发行可以买两套，分别记录品相、价格、收货时间和存放位置。
4. **盘片**：套装里的 CD1、CD2、DVD、BD 等。一个副本可以有多个盘片，盘片与光驱绑定。
5. **内容单元**：曲目、正片、花絮、章节。播放记录指向实际盘片及内容，避免把花絮的进度当成电影进度。

音乐／影像是内容分区，CD／DVD／BD／SACD／黑胶等是物理载体。演唱会 BD 可以归入音乐；电影原声 CD 可以归入音乐；混合 CD+BD 套装是一套实物，多种盘片，不拆成两笔购入金额。支持跨分区引用，但统计按副本主键去重。

首版数据层容纳多载体，播放层逐种声明支持。能收藏 SACD 不代表能播放 SACD。未来书籍、游戏、磁带作为品类插件，不能靠在所有页面不断新增格式判断来实现。

## 3 信息架构与主流程

左栏保留“音乐、影像、想购入、在途、播放历史”；底部为“光驱、助手、设置”。不设填满欢迎语、趋势卡片和说明段落的首页。默认直接进入上次使用的收藏架，恢复筛选和滚动位置。

主区顶栏为分区名、搜索、添加。第二行显示总套数、总盘数及金额，然后是状态、载体、排序、视图切换。金额按币种分组；不能直接把人民币、日元、港币相加。

### 条码或品番入库

“添加”打开居中面板，输入模式为条码／品番／关键词／手动。条码扫描枪按键盘设备接收，明确输入焦点，保存扫描原文，保留前导零。校验条码校验位不能证明发行唯一。

查询显示具体发行匹配项：标题、艺人、年份、地区、厂牌、品番、载体数量、包装及封面；展开后看曲目和来源。多个结果必须选择。只有确切供应商 release ID 已绑定或用户显式开启且匹配规则满足的自动流程才直接入库；不能仅凭标题相似自动选择。

选定后填写副本信息：状态、收藏时间、购买时间、收货时间、价格、币种、购入位置、存放位置、购买链接、品相、备注。可以先不填价格。已有同版时默认提示“新增副本”或“查看已有”，不误覆盖。

扫描队列每项独立记录查询、等待选择、完成、失败；断网可暂存待查询条码。供应商限流由服务层排队，不让扫描速度直接制造请求峰值。重复扫码可回到队列条目，但用户明确新增第二副本时不得去重掉。

### 搜索与筛选

默认搜索本地库，不联网；提供清晰的“搜索 Discogs”动作进入外部数据库检索。全文包含标题、艺人、品番、条码、厂牌、标签、备注。保留原始标识，不把大写、小写或破折号差异猜成等价编号；自然语言全文搜索可以提供相关性排序，但唯一键匹配使用精确值。

筛选支持品类、载体、状态、地区、年份区间、厂牌、品相、模型有无、购买店铺、价格区间与币种。范围价格必须先选币种。保存常用筛选为视图，筛选条件可清除并可键盘操作。

### 购买与统计

状态为“想购入 → 在途 → 已购入”，允许纠正；另有“已取消、已转出”，保留交易史。付款和所有权分开：在途可以已经付款，想购入的报价不是成本。

顶部“收藏”统计已购入且仍持有的副本；“盘片”统计其中明确登记的盘片；“购入金额”统计这些副本的净购入成本。想购入和在途各自显示数量与预算／已付款，不能混入已持有总价。

金额用整数最小货币单位和币种精度表，禁止浮点金额。未知金额用空值而不是零；免费购入显式为零。邮费、税费、折扣作为订单成本项，跨物品分摊保存方法及结果，避免重复加总。退货、退款、转售收益单独记录；净支出和现有收藏成本是两种不同指标。

初期采用原币种分组；以后换算为展示币种时保存汇率来源、时间和计算口径，标注为折算。收藏数显示“套”和“张”，避免多碟盒的数量歧义。

## 4 陈列与详情

默认采用浅暖灰背景、深墨色文字和单一低饱和蓝绿色强调色。收藏架为浅色层板，碟盒竖放，底部接触阴影与背后柔和投影始终存在。封面是视觉中心，UI 不与藏品争夺注意。

提供三种视图：竖放架突出背脊与盒厚；封面网格提高辨认效率；表格适合批量整理。每种视图共享选择状态、筛选、排序和虚拟化数据源。

有完整模型：架上使用低成本闭合外观或预渲染图，点击后加载真实模型并进入检视；不是同时在整架运行数百个高面数模型。无模型有封面：使用 CD／DVD／BD 通用盒体，或用户指定的纸套，保留静态阴影。封面也没有：用标题、作者和载体的纯排版外观，不生成假专辑封面。

现有模型包没有通用实物尺寸、背脊图和竖立方向契约。架上方向、厚度与尺寸作为新项目独立展示配置保存，不能从标题、节点名或 Z-up 自动猜测。默认封面模式可立即使用；真实异形模型竖放先由用户设置展示姿态并保存缩略图。

详情分成实物检视区和可滚动信息区，保留返回原位置的路径。信息标签只使用“资料、曲目／内容、购入、历史”。“版本”区域显式显示当前具体发行，不能切换版本后悄悄改变已有实物的归属。

模型操作继承 AtelierPublisher 的规则：取出跟随当前部件、不隐藏周围部件；收回按物理路径逆序；单件查看退出恢复先前镜头；连续翻页不重新取景。动画中再次操作时应中断或排队到合法状态，不产生两个相互竞争的镜头控制器。

## 5 光驱和播放

设备面板按真实设备列出型号、盘符、当前盘片、识别状态、播放能力与弹出动作。插盘后出现一次可操作通知，例如“《作品名》· CD 1 已插入 · 播放”；同一插盘事件不能重复通知。程序启动时扫描一次，随后接收系统事件并去抖，多光驱独立管理。

识别顺序为：读取设备及介质类型 → 读取 TOC 或光盘结构指纹 → 查本地绑定 → 必要时查外部元数据 → 交给用户确认发行／盘片 → 保存本地绑定。标签名、曲目数、时长、目录只能提供匹配证据，不能代替确切发行身份。没有匹配时允许“绑定已有盘片”或“新建条目”。

视频盘先列标题、播放列表、时长、章节、音轨、字幕及节目链信息，再让用户分配正片／第几集／花絮。DVD、BD 分别解析，不以最大文件自动决定正片。BD 无缝分支、播放列表混淆、多角度、重复片段需要真实样盘验证；不确定就保留未分配状态。手工分配与设备盘符解耦，换光驱后仍可匹配。

播放界面为独立内容区域或窗口；原生播放画面不依赖 WebView HTML video 解码所有光盘。首个技术验证比较 LibVLC 与 libmpv 的画面嵌入、菜单、字幕、硬件解码和分发成本后锁定首发后端。播放命令统一，后端不直接访问收藏数据库。

播放历史包括来源、版本、副本、盘片、标题／曲目、开始时间、最近位置、有效播放时长和结束原因。按事件写入、定期合并位置；暂停不计播放时长，跳进度不算已观看；崩溃最多丢最近一个检查点。DVD/BD 菜单与分支无法稳定恢复时退回标题／章节选择，不能假装可精确恢复。

**BD 全区能力**：产品保留播放器区域配置和后端能力检测，目标覆盖已验证的 A／B／C 区样盘。区域判断与 AACS、BD+、BD-J、驱动器兼容性分别记录。libbluray 本身不等于能播放所有商业受保护 BD，纯软件也不能保证任意光驱、任意碟片可用；该能力必须通过专项验证后再标为完成。UHD BD 单列能力矩阵，不随普通 BD 一并承诺。

无法在内置后端播放时，可以配置已有外部播放器并把已确认的盘片交给它；若外部播放器不提供状态接口，历史只记录启动事件，不伪造完整播放时长和进度。

## 6 数据源与网易云

Discogs 负责音乐发行元数据，不把它的用户收藏直接当作本地所有权记录。保留来源 release ID、master ID、来源 URL、获取时间、原始响应版本和字段出处。手动改动以本地覆盖层保存，刷新来源不覆盖用户的购入信息或人工修订。

网易云通过可更换适配器补充歌曲、歌词和服务实际允许的播放地址。匹配以用户确认后的歌曲 ID 绑定；同名歌曲、重制版、现场版、混音版不能凭名称自动相互覆盖。数字曲库的专辑归属不改变实体版本曲序。

可复用 `ReversedFutureMusicApi` 的已确认四种操作：`search`、`metadata`、`detail`、`playback`。Rust 后端调用，凭据存在系统凭据库，前端只得到必要结果。网络地址临时获取、失效再解析；试听与完整播放状态分别显示。社区 API 下线、限流或返回不可播放不影响本地收藏与光盘播放。

视频资料源只先定义能力与导入映射，不填写猜测的端点。选择服务之后先留真实响应样本，再实现适配器。

Discogs 的缓存、归属标识和 Restricted Data 边界见集成文档。不能把“本地优先”写成对所有第三方 API 内容永久复制的承诺。

## 7 AI 助手

采用 agent harness 的工程架构：模型连接器、会话状态、上下文装配、工具注册、策略执行、结果校验、检查点、日志、评估分离。它是系统架构实践，本项目不会声称通过某个未指定的统一标准认证。

侧栏助手可以回答“我有哪些日版”“哪些在途”“这张的另外几个版本”“把刚收到的这一套设为已购入”。工具调用走与 UI 相同的应用用例，不能直连 SQLite、随意执行 SQL、shell 或绕过供应商限制。

读操作可直接完成；单条可撤销操作在用户明确授权范围内执行并提供撤销；批量修改先展示具体差异；永久删除、支付、网站发布、导出私人信息等需要独立授权。站外购物页、曲目说明与模型元数据都是不可信数据，不得作为权限指令。

会话保存工具输入摘要、数据版本、执行结果和错误，凭据与完整 Cookie 永不进入提示词。模型重试不能重复新增副本；写操作用幂等键和预期版本号。上下文只带当前问题必要的库记录；Discogs Restricted Data 不默认送给外部模型。

支持兼容 API 和不同厂商适配器，但“兼容”必须经工具调用、流式输出、结构化响应和取消行为测试。设置提供地址、模型名、连接测试与密钥录入，不把任意响应都按同一 JSON 路径解释。

## 8 本地数据与维护

SQLite 保存领域数据，图片和模型以内容哈希存到独立资产库；数据库仅保存资源引用、类型、大小、摘要和来源。采用事务、外键、迁移、WAL 与在线备份机制。备份包含一致性数据库快照、资产清单、校验值及应用版本；不能直接复制正在写入的主数据库文件当作完整备份。

默认关闭远程同步。后续若接个人网站，只通过显式导出／同步适配器发布选中的公开字段，购买价格、地址、备注和凭据默认不公开。现有网站音像隔离规则不由本项目自动改变。

导入模型限制大小、几何预算、引用和格式版本；没有脚本执行。WebView 用 CSP、受限 Tauri capabilities 和明确 IPC 命令，不给 UI 任意文件访问、网络或 shell 权限。模型读取和数据库操作在 Rust 用例层二次校验。

## 9 发布和自更新

私有 GitHub 仓库保存源码与版本记录。正式产品采用 Windows NSIS 安装包作为第一条发布路径，其他包型后续按需求加入。CI 构建前先测试，产出安装包、Tauri 更新签名、更新清单和 SHA-256 校验文件。

私有仓库不能靠一个公开 Releases 下载链接完成匿名更新，也不能把长期 GitHub 令牌写进应用。推荐小型更新网关：应用使用个人设备凭据访问网关，网关用仓库读取权限获取固定仓库的发布资产，返回签名清单和受控下载。个人本机令牌方案可作为无需服务的替代，但凭据必须由用户配置且只保存在系统凭据库。

更新必须验证签名；下载中断可重试；更新前完成备份和数据库迁移预检。二进制回退不等于数据库回退，需记录最低兼容版本并通过备份恢复处理不可逆迁移。Windows 代码签名用于发行者身份，与更新签名分开配置。

用户要求的本地安装包清理规则：先验证远端上传成功、名称及大小正确、下载后哈希和签名正确，再逐个删除本次构建清单中的明确安装包文件；保留源码和构建记录。上传失败或验证失败时不删除。CI-only 构建不产生本地安装包；不执行目录递归清理。

## 10 首版完成标准

能离线完成手动入库、同版多副本、多碟套装、购买状态流转、原币统计、搜索筛选、备份恢复；联网时能经 Discogs 精确选择发行版本；收藏架可用默认盒体和真实模型检视；断网或外部服务失败不损坏本地库。

播放器、全区验证、购物价格和 AI 都有独立里程碑，不阻塞基本收藏管理，也不能在尚未接入时显示成功。完整依赖、版本与验收条件以 `ROADMAP.md` 为准。
