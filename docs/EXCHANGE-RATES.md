# 每日汇率换算

2026-10-22，开发预览，未发布 GitHub 发行版。

## 使用

退出当前程序，打开 `target/release/DiscAtelier-exchange-preview.exe`，进入「设置 → 汇率」。

1. 在[接口盒子](https://www.apihz.cn/api/jinronghuilv.html)个人资料中查看开发者 ID、KEY，填入设置。接口地址固定为文档的普通域名线路，不需要自行部署服务。
2. 将参考换算设为「每天更新」，选择显示币种并保存。支持现有收藏币种 CNY、HKD、JPY，默认 CNY；KEY 留空会保留已保存的对应账号密钥。
3. 设置列出最近汇率及接口给出的更新时间。可点击「立即更新」手动重试，至少间隔一分钟；关闭后保留配置但不自动请求，移除 KEY 会同时关闭换算。
4. 购入输入框下、购入详情、整理列表中，外币价格下方出现参考换算；菜单原有分币种金额保留，新增参考合计。

原始币种、金额和购买日期均不改写。这是当前参考汇率，不是购买当日的结算汇率。

## 更新和缓存

- 以电脑本地日期为每天边界，启用后启动应用、恢复前台或跨日时自动检查。应用持续打开时最多一分钟内检查到跨日；关闭应用期间没有独立后台进程，下次打开再检查。
- 每天自动发起一轮更新，两个外币对显示币种各请求一次；持久化当日尝试记录，重复切换页面、重启和并发调用不会重复自动请求。
- 失败后保留最近有效汇率及日期，当天不反复自动重试，用户可手动更新。显示「旧缓存」表示来自之前日期的请求；设置始终展示接口的 `uptime`，不把本机检查日期当作接口数据日期。
- 缺少任一非零金额币种的汇率时，不把部分金额伪装成完整折算合计。显示币种改变后不会混用之前目标币种的缓存。
- 请求金额固定为 `money=1`，不向汇率服务发送收藏名称或实际购入金额。全部换算使用本地整数／十进制有理数计算，日元按整数元，人民币和港元按分；混合金额合计后统一四舍五入。
- 配置与最多两条汇率保存在应用数据目录 `exchange-rates.json`，与收藏 SQLite 库独立，无追加历史增长。KEY 按开发者 ID 绑定保存在 Windows 凭据管理器，不在此 JSON、收藏库或收藏备份中。
- 使用文档的普通 ID／KEY 接口；如果账号启用了接口盒子的可选动态 `dkey` 校验，本轮配置尚未接入该可选协议。

## 接口证据

官方文档：<https://www.apihz.cn/api/jinronghuilv.html>。

实际读取了文档公开示例，并用同一公开演示凭据核验 `JPY→CNY`、`HKD→CNY` 的单位金额响应。未使用、读取或保存用户的实际 KEY。

- 实际 `rate` 是十进制字符串，文档示例是数字；适配器同时支持这两种已核实类型。
- 实际日元单位响应 `result=0.0423`，`rate="0.042290632517137"`；港元响应 `result=0.8526`，`rate="0.85257953951811"`。因此本地计算使用完整 `rate`，不放大已舍入的 `result`。
- 原始响应 `uptime="2026-10-21 08:00:02"`，作为固定解析测试资料保存在 `apps/desktop/src-tauri/src/exchange/fixtures/`。这些数字是测试采集记录，不是程序内置默认汇率。
- HTTP 固定为 HTTPS 官方端点、禁止重定向、超时与响应大小有上限；错误不回显可能含 KEY 的原始接口消息或请求 URL。
