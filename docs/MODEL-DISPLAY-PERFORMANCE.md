## 结果

| 首次显示观测中位数 | 12.76 秒 | 6.45 秒 |
| 三次范围 | 12.71–12.78 秒 | 6.37–6.49 秒 |
| 第一次 | 12.78 秒 | 6.45 秒 |
| 第二次 | 12.76 秒 | 6.49 秒 |

中位数减少 **6.31 秒，49.5%**。这些是本机本样本的结果，大型模型仍需要数秒准备，不代表任意模型或设备的固定耗时。

### 测量范围

- 模型 33,806,212 字节，SHA-256 `43f6ded4137251d1cb1745cbf55a0f664a42cb9e379da719397abe12e9afa515`。原包不重编码、不修改。
- 比较上一轮原生导入完成后的 Release 与本轮最终 Release，不混用 Debug。
- 每次使用全新进程、数据库和 WebView 目录。先把同一模型保存入库，再重新载入页面；测量时没有已解析模型缓存。
- 从最早的模型显示计时开始，等到当前模型标记就绪，再等待两次 `requestAnimationFrame`。两份构建使用相同脚本和观察方式。
- 该值包含加载、绘制提交、自动化观察和帧调度，不能当作 GPU 查询计时，也不包含选择文件、导入保存或整个应用启动。
- 程序都在 D 盘、隔离库在 F 盘；正式计时不同时编译或运行另一项原生测试。没有清空系统文件／驱动缓存，也未锁定桌面其他应用负载。
- 优化后测完再复测旧程序；更早的旧程序三次中位数为 13.35 秒，本文采用较近的复测值 12.76 秒。
- `performance-harness` 仅用于选择输入和隔离数据库。普通 Release 不含这些测试入口；渲染代码相同。

## 实现

| 原来 | 现在 | 原因 |
| --- | --- | --- |
| 完整模型经 IPC 到主线程，再送入 Worker | Rust 只读协议直接由 Worker 获取 | 减少主线程转发；保留完整校验 |
| 每次打开重新解析，切换时旧任务可能继续 | 最近一个解析结果缓存；共享请求独立取消，最后一个消费者离开则终止 Worker | 减少重复工作，旧结果不覆盖新收藏 |
| 贴图逐张加载 | 保持原 TextureLoader，最多四张并发，失败和取消统一释放 | 缩短准备并控制并发资源 |
| 首次 render 才陆续准备程序参数 | 提前编译主画面／透射变体并准备参数信息 | 减少绘制期间同步等待 |
| 旧阴影类型在首次绘制被 Three 自动替换 | 一开始采用这个固定版本实际使用的 PCFShadowMap | 避免提前编译后又因类型变化失效，实际阴影算法不变 |
| 就绪状态与首帧绘制时机分离 | 完整首帧后才标记就绪，封面与模型交叉淡入 180 ms | 加载期间保持原展示，减少空白闪现 |

排查时确认，仅改传输／贴图并发或关闭成功着色器日志没有改善完整观测时间。最终保留原有错误检查；主要收益来自正确的着色器准备和避免首帧失效。固定 Three 源码的 `WebGLShadowMap.render` 明确把 PCFSoftShadowMap 替换为 PCFShadowMap，`renderTransmissionPass` 定义透射通道的编译环境。

`prepare-renderer.js` 将依赖固定 Three 内部程序接口的部分单独封装；更新 Three 时需重新核对。临时 1×1 目标仅用于编译环境，没有绘制低分辨率模型，也没有改变实际画面分辨率。

- 保留原贴图尺寸、纹理属性、各向异性、像素比、抗锯齿、材质效果、光照、2048 阴影图和曝光。
- 动作、轨迹、歌词本取景及返回路径源码哈希不变。运行库原始 22 文件中仅 README、资源加载、挂载及 viewer 四处发生变化，另增贴图加载与渲染准备模块。
- 已检查优化前后的完整唱片检视截图；原生测试验证翻盖开合、按原路径收回、旋转缩放及完整唱片渲染。
- 同一检视画面的 1800×1200 截图对照：每通道最大差值 2／255，全图每通道平均绝对差约 0.07／255；不是逐像素完全一致。差异位于模型区域，原始图片与比较结果路径记录在 JSON 中。
- 加载过程中保留封面；不添加额外按钮或提示文字。快速换收藏／关闭检视会释放旧场景，减少动态模式关闭交叉淡入。
- Rust 已开始的 SQLite 读取不强制中断，但取消后的数据不会继续被旧 Worker 解析或替换当前展示。
