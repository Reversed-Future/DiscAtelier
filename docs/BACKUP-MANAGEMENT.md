# 备份管理与项目空间

此功能纳入 0.1.9 正式发行；下方预览路径作为构建历史记录保留，发行验证后清理本地预览。

## 设置 → 数据

备份占用默认折叠，只显示总大小和份数。点击“管理”展开日期、文件名与大小列表，列表超过 240 px 单独滚动。勾选文件后，“删除所选”会显示份数和不可恢复提示；再次确认才逐个删除。没有自动清理规则，也不会默认勾选任何备份。

统计只读取应用数据目录 `backups` 下直属普通文件的元数据。`.sqlite3` 和失败留下的 `.partial` 文件可手动选择；辅助文件计入占用但不可删除，子目录和链接不会跟随。不会读取备份中的收藏内容，也不要求收藏服务成功打开，因此较新数据库版本不会阻挡查看和管理备份。

删除命令只接受一个文件名和列表中的状态摘要，不接受任意路径。限制在应用备份目录，拒绝路径跳转、链接、目录、状态已变化的文件及存在 SQLite 日志的备份。与应用内备份、恢复和更新使用同一把锁；Windows 拒绝删除被占用文件时，不强制关闭文件或进程。当前 `library.sqlite3`、封面、模型、凭据和其余备份不在删除范围内。

每个文件分别返回结果，首个错误发生后停止后续删除，并保留已完成的删除计数。选择刷新后重新确认，避免根据过期列表继续操作。

- `cargo test -p discatelier-storage --test update_backup`：3 项通过，包含较新数据库 schema 和 WAL 一致性快照。
- `npm test`：53 项通过，含串行删除、失败停止和部分完成结果。
- `cargo clippy --workspace --all-targets -- -D warnings`、TypeScript／Vite 构建通过。
- 所有删除测试只操作新建的隔离测试文件，没有打开或删除用户备份，没有操作用户窗口或光盘。实际界面由用户手动验收。

Tauri Release 预览构建通过：`target/release/DiscAtelier-backups-preview.exe`，与构建主程序 SHA-256 一致：`8a7a72e9f7e405e552b237cff058254772702f34021a1239229a3d15c5e9f6b7`。共享运行时的 Node、四个入口模块及清单哈希校验通过。需保留同目录 `netease-runtime`；没有启动程序、生成安装包或更新 GitHub 发行。

手动测试：进入“设置 → 数据”，核对占用，展开管理；可先新建一份测试备份，选中它后检查取消不会删除，再确认只删除这一份。多选时确认份数和大小正确，删除后列表及总量更新。保留真正需要恢复的旧备份。

去重按同一卷的文件标识进行，不是磁盘分配簇的物理占用测量；分组去重归属与遍历顺序有关。后续构建会改变这些数字。

主要来源是 Rust 的增量编译、依赖产物和调试符号。项目 `target/debug/incremental` 按路径相加约 16.59 GiB，`target/debug/deps` 约 14.15 GiB。运行时隔离测试通过 `fs::hard_link` 共享同一个 Node 程序，因此简单逐路径累加会明显高估测试产物。用户收藏与自动备份默认位于 `%LOCALAPPDATA%\com.reversedfuture.discatelier`，不是项目缓存。

用户已授权以后每次新版发布并验证上传成功后，清理旧版程序和不再需要的构建缓存。执行前记录明确文件清单，逐个文件删除；不递归删除目录，不清理用户收藏、备份、签名材料、源码或当前必要运行资源。本次仅排查，没有执行缓存清理。
